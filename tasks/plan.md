# Implementation Plan: ClaimLens

Source: [SPEC.md](../SPEC.md). Build autonomy (confirmed): checkpoint after each full phase below — implement the phase, verify it independently, stop for review before starting the next.

## Overview

ClaimLens is built as the pipeline SPEC.md defines: quality gate → detection → cost estimator → triage engine → policy retrieval → Gradio UI, each stage independently buildable and testable, matching blueprint §5's design principle. Because the pipeline itself is already a sequence of independently-verifiable stages, phases below follow that pipeline order directly rather than needing separate vertical-slice restructuring — each phase *is* a vertical slice (a stage that works and is tested end-to-end for its own scope before the next stage depends on it).

## Architecture Decisions

- **Phase order follows the pipeline**, not a horizontal split — each phase leaves a working, independently-tested component, per SPEC.md Testing Strategy.
- **Data and models are gitignored**, generated by scripts, not committed wholesale — keeps the repo reviewable; price table and policy clauses (small, hand-authored) are the exception and are committed.
- **Git repo stays local until the deployment phase** — no GitHub remote is created/pushed until Phase 9, per SPEC.md Boundaries ("ask first" on anything touching GitHub/HF naming). Local commits happen after every phase checkpoint.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| `ultralytics`/`torch` lack Python 3.13 wheels | Med | Fall back to a pinned older Python via `pyenv` for the training env only, discovered and handled at Phase 0/3 |
| MPS training budget (~30-60 min) yields poor mAP | Med | Blueprint §8 explicitly allows reporting honest numbers; Colab notebook documented as the stronger-training path, not required to ship |
| Roboflow export format doesn't match YOLO-seg expectations out of the box | Low | Verify export format immediately in Task 2 before building downstream on an assumption |
| Redefined `structural_or_hidden_damage_suspected` rule (no fixed-view checklist) is harder to get right than the blueprint's original design | Med | Deferred explicitly to Phase 5's own checkpoint — not decided now, decided with test cases in hand |

## Open Questions
